# 学习任务协议：投影是否真的降低认知负担

目的：对比“mathlib 文档 + Loogle”和“概念投影 + 按需展开”两种工作流。

## 目标

二选一：

- `List.map_comp_map`（List 领域，docstring 覆盖较好）
- `Filter.coext`（Filter 领域，实例/机器更多，文档覆盖较低）

## 条件

### A：文档 + Loogle

- 只允许使用 mathlib4 文档、Loogle、LeanSearch；
- 不允许打开 `out/*.projection.md`。

### B：投影 + 展开

- 先看对应的 `out/<target>.projection.md`（聚焦半径 2）；
- 需要时可以沿概念依赖展开到具体声明；
- 允许再用 Loogle 查签名/例子。

## 任务

1. **复述命题**：不看资料，用自己的话写出定理在说什么。
2. **列出先修**：列出理解命题所需的 3–7 个概念，并说明为什么。
3. **找关键引理**：找出证明中最关键的 3 个引理/策略，说明它们的作用。
4. **小练习**：用该定理完成一个等价改写或小证明。
5. **一周后回忆**：不看资料，复述命题、关键引理和证明思路。

## 判读

- 如果 B 组在“列出先修”和“找关键引理”上明显更快，且一周后回忆不差，说明投影有产品价值；
- 如果 B 组只是“看起来更整齐”，但实际任务没有变快，说明当前的聚焦/概念层还不够，需要继续改；
- 如果 A 组更快，说明投影引入了额外认知负担（节点太多、机器噪声未折叠），应优先解决实例/内部管道的折叠问题。

## 备注

- 同一目标不要在同一天连续做 A/B，避免记忆污染；建议隔天交叉。
- 投影文件是静态 Markdown；正式产品中“展开”应由交互完成，这里用文件代替。
- 记录真实的卡点和误解，比打分更有价值。
