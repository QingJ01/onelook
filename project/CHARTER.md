## 1. 一句话

把 OneLook 从“思维导图工具”演进为“以形式化库为 substrate、以个人图笔记为 overlay、以多投影为界面的学习工作台”。

## 2. 问题

思维导图是树形投影：它把多关系、多父、环、n 元陈述压成单一父子层级。mathlib 的学习痛苦是这一问题的极端案例：

- 声明图巨大，文件/命名空间按实现组织，而不是按学习顺序；
- 搜索（Loogle、LeanSearch）返回孤立声明，不告诉你它在知识网络中的位置；
- docstring 往往默认读者已有背景，符号与类型类层级密集；
- 学习者真正需要的“先学什么、怎么用、我在哪”没有对应视图。

当前 OneLook 的数据模型是严格的树（`src/types/index.ts:40-57`），连线由父子关系推导（`MindMapCanvas.vue:387-422`），导入导出会丢弃 XMind relationships 等跨节点关系。它无法承载上述多面结构。

## 3. 产品主张

1. **mathlib 形式图是公共的、只读的、按版本固定的 substrate**：声明、类型级/证明级依赖、实例、simp、import。
2. **用户在其上编写个人图笔记 overlay**：概念、笔记、例子、错误记录、先修关系、学习状态。
3. **系统提供脚手架**：锚点解析、从目标播种、粘贴解析、缺口检查、失效检查。
4. **视图是投影**：先修树、API 树、概念地图、形式 vs 个人对比、复习视图。
5. **思维导图保留为其中一种视图**，而不是数据模型。

## 4. 目标用户

- 主要：正在学习 Lean 4 / mathlib、需要建立数学概念地图和可执行笔记的学习者。首个用户就是项目作者。
- 次要：其他形式化库（Coq / Isabelle / Agda）的学习者；未来可扩展到非形式化知识源。

## 5. MVP（垂直切片）

不做全量 mathlib。选一个当前学习目标，只做它的依赖闭包。

### 目标选择标准

1. 当前学习正在用（Ch01–Ch02 逻辑/归纳，或正在卡住的 mathlib 定理）；
2. 依赖闭包可控：目标闭包小于约 500 个声明，概念聚合后小于约 100 个节点；
3. docstring 覆盖尚可；
4. 有跨模块依赖，能体现投影价值。

### 默认候选

- `Nat.add_comm`：基础、熟悉，适合验证抽取管线；
- `List.length_append`：结构简单，适合验证概念聚合；
- `Filter.Tendsto`：经典痛点，闭包较大，作为压力测试备选。

最终目标在 M1 开始时按上述标准确定。

### MVP 必须包含

1. 固定 mathlib commit 的抽取：声明、类型、证明项、docstring、实例、simp、import；
2. 类型级依赖与证明级依赖分开；
3. 目标的后向依赖闭包 + 剪枝 + 概念聚合（20–50 个概念，可人工审核）；
4. 个人 overlay：概念/笔记/错误节点，锚定声明；`prerequisite-of` 等边；known 状态；
5. 三个投影：个人先修树、API 树、形式 vs 个人对比；
6. 脚手架：从目标播种、粘贴解析、缺口检查、失效检查；
7. 用真实学习任务评估。

## 6. 非目标（M0–M4 不做）

- 全量 mathlib 图浏览器/编辑器；
- 自动构建全 mathlib 概念层；
- Neo4j 级数据库能力（Cypher、ACID、集群）；
- 多人协作、社区市场、账号系统；
- 移动端；
- 一次性重写现有导图 UI；
- 修改 mathlib 上游。

## 7. 架构原则

1. **substrate 只读、版本化；overlay 可编辑、本地优先**。
2. **两种节点粒度**：声明引用节点 vs 概念节点（一个概念可锚定多个声明）。
3. **边有类型、方向、来源（auto / user / shared）、权重**。
4. **focus 是一等状态**：目标、已知集合、边策略、深度、阈值；视图是 focus 上的投影，不是数据模型。
5. **自动建议，用户确认**；形式图与个人图可对照校验。
6. **先垂直切片，后架构重构**；避免大爆炸。

## 8. 成功指标

### M1（抽取）

- 固定 commit 下可复现；
- 闭包完整覆盖目标陈述的类型级依赖（人工抽查）；
- 能区分类型级 / 证明级 / 实例 / simp 边；
- 输出带 docstring 覆盖率的 graph JSON；
- 概念聚合后，投影节点数控制在约 100 以内且仍可读。

### M2–M3（overlay / 投影）

- 20–50 个概念笔记可锚定，锚点解析率 > 95%；
- 缺口检查能指出至少 3 个“用户遗漏但形式图需要”的概念（人工判定）；
- 三个视图能分别回答“先学什么 / 怎么用 / 我在哪”。

### M4（学习效果）

- 与 docs + Loogle 工作流对比：找引理时间、无效搜索次数、自评理解度、一周后回忆率；
- 不追求统计显著，先看方向和质性反馈。

## 9. 里程碑

| 阶段 | 内容 | 产物 | 门槛 |
|:---|:---|:---|:---|
| M0 | 立项与环境盘点 | 本章程、ADR、Spike 计划 | 目标与环境确认 |

## 10. 风险

| 风险 | 影响 | 缓解 |
|:---|:---|:---|
| 原始依赖图噪声大 | 图不可读 | 类型/证明边分离、权重、概念聚合、证明管道折叠 |
| 概念层策展成本高 | 冷启动失败 | 只做目标闭包；播种 + LLM 草稿 + 人工审核 |
| mathlib 版本漂移 | 锚点失效 | commit 固定；别名解析；失效报告与迁移 |
| 浏览器规模限制 | 性能差 | 按需加载子图；预计算；必要时嵌入式图引擎 |
| 个人图维护成本 | 用户放弃 | 笔记优先、粘贴解析、自动建议、图后生成 |
| 学习效果不确定 | 产品价值不成立 | M4 真实任务评估；随时止损 |

## 11. M0 的第一步

1. 固定数据环境（已完成）：mathlib `db584cd6d46c92f209a44c0f1c829460d327499d`，Lean `v4.33.0`。
2. 选定 MVP 目标（M1 开始时，按 §5 标准）。
3. 写抽取 spike：先输出目标闭包的声明图与统计，不做 UI。
4. 用 Markdown / Graphviz 手工投影一版先修树，人工判断是否比 docs + Loogle 更有用。

**结论：第一步不是重构代码，而是用最小成本验证“抽取 → 概念聚合 → 投影”这条链路。**
